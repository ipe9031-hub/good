PPT AI Studio — Microsoft PowerPoint AI Add-in 통합 개발 지시서

0. Codex에 대한 최상위 지시

당신은 Microsoft 365 Office Add-in, React, TypeScript, PowerPoint JavaScript API, OpenAI API, Supabase, Vercel에 전문성을 가진 시니어 풀스택 개발자다.

사용자가 실제 Windows용 Microsoft PowerPoint 안에서 사용할 수 있는 상용 제품 수준의 AI 애드인을 개발한다.

중요: 단순한 웹사이트나 PPT 파일 생성기가 아니다. 실제 PowerPoint 리본 메뉴에 등록되고, PowerPoint 내부 슬라이드와 개체를 조작하는 애드인이다.

기획된 전체 기능을 프로젝트 요구사항으로 보존하되, 한 번에 수십 가지 기능을 미완성 상태로 구현하지 않는다.

실행 가능한 MVP를 먼저 구축한 다음 기능별 모듈을 순차적으로 구현한다.

기존 GitHub 저장소에 연결되어 있다면 먼저 소스코드, 패키지, 설정, 배포 구조를 분석한다. 기존 Supabase 및 Vercel 연결을 가능한 한 재사용하고, 정상적으로 동작하는 코드는 불필요하게 삭제하거나 교체하지 않는다.

사용자와 별도로 합의하지 않은 기능을 임의 추가하지 않는다.

4. AI 장표 생성 엔진

4.1. 핵심 목표

사용자가 문장과 사진을 입력하면 AI가 PowerPoint 장표를 자동 제작한다.

예시 명령:

"이 사진 4장을 활용해서 현장 안전점검 결과 장표를 만들어줘. 16:9 비율로 하고 임원보고용으로 깔끔하게 구성해줘."

"내일 아침조회용 장표로 만들어줘. 작업자가 멀리서도 볼 수 있도록 제목과 강조 문구를 크게 만들어줘."

"이 장표를 조금 더 고급스럽게 바꿔줘."

"제목만 수정하고 나머지는 그대로 유지해줘."

AI는 사용자의 자연어 명령과 입력 자료를 분석하고 장표를 구성한다.

4.2. 두 가지 장표 생성 모드

A. 이미지형 장표

AI가 하나의 완성된 이미지로 장표를 제작한다.

AI 이미지 생성 API 활용

16:9 비율 기본 지원

높은 해상도 출력

PowerPoint 슬라이드에 이미지 삽입

이미지 재생성 및 부분 편집

원본 사진 및 자료 보존

B. 편집형 장표

PowerPoint에서 직접 수정 가능한 장표를 제작한다.

제목: 텍스트 상자

본문: 텍스트 상자

사진: 이미지 개체

강조 표시: 도형 개체

화살표: 도형 또는 연결선

배경: 슬라이드 배경 또는 도형

가능한 한 각 요소를 개별 PowerPoint 개체로 유지한다.

AI가 편집 가능한 슬라이드를 구성하도록 구조화된 레이아웃 JSON을 설계한다.

예:

slideWidth

slideHeight

background

elements

elementType

position

dimensions

typography

colors

sourceReferences

AI가 직접 무제한적인 Office.js 코드를 생성해 실행하게 하지 않는다.

AI는 허용된 편집 작업 스키마를 생성하고, 서버와 클라이언트가 이를 검증한 후 실행한다.

4.3. 공통 요구사항

현재 슬라이드에 삽입

새 슬라이드에 삽입

기존 슬라이드 교체

슬라이드 여러 장 생성

원본과 편집본 비교

이미지형 장표를 완전한 편집형 장표로 자동 변환할 수 있다고 보장하지 않는다. 이미지 속 문자와 요소를 분리할 때는 인식 정확도 및 편집 가능 범위를 명확히 안내한다.

5.1. 사진 삭제 시 자동 재배치

사진 4개 중 1개를 삭제하면, 나머지 3개의 사진을 적절히 재배치할 수 있어야 한다.

지원 모드:

자동으로 빈 공간 채우기

기존 크기를 유지하며 당기기

기존 위치 유지

사용자 지정 배치

사진이 4장에서 3장, 2장으로 바뀌어도 선택 영역 내에서 균형 있게 재배치한다.

5.2. 사진 위치 맞교환

사용자가 사진 A와 사진 B를 선택하면 위치를 서로 교환한다.

지원 방식:

사진 내용만 교환

사진 개체 위치 교환

사진과 설명문 함께 교환

사진과 번호, 마킹까지 함께 교환

사진 외부의 제목, 배경 등 변경 대상이 아닌 개체는 보호한다.

5.3. 사진 교체 시 레이아웃 유지

기존 사진의 위치·크기·테두리·자르기 설정을 유지하면서 이미지 내용만 교체할 수 있도록 한다.

이 기능은 매우 중요한 핵심 기능으로 구현한다.

OpenAI GPT를 이용하여 PowerPoint 슬라이드의 내용을 원하는 언어로 번역한다.

단순 문자열 치환이 아니라 문맥을 고려한 자연스러운 번역을 제공한다.

22.3. 원문 처리 방식

반드시 다음 세 가지 모드를 모두 구현한다.

모드 A. 원문 교체

기존 한국어 텍스트를 번역된 언어로 교체한다.

가능한 한 기존 글꼴·색상·위치·텍스트 상자의 서식을 유지한다.

모드 B. 원문 유지 + 번역문 추가

원본 텍스트를 삭제하지 않는다.

번역문을 새 텍스트 상자로 추가한다.

배치 옵션:

원문 아래

원문 위

원문 오른쪽

원문 왼쪽

사용자 지정 위치

번역문과 원문의 글꼴·크기·색상을 개별 설정할 수 있게 한다.

모드 C. 원본 슬라이드 유지 + 번역 슬라이드 추가

현재 슬라이드를 보존한다.

원본을 복제하여 번역된 슬라이드를 새로 생성한다.

원본과 번역 슬라이드를 연속으로 배치하거나, 번역 슬라이드들을 별도 구간에 모을 수 있도록 한다.

23. 개발 대상에서 제외할 기능

사용자가 명시적으로 제외한 기능은 독립 모듈로 개발하지 않는다.

디자인 학습 및 템플릿 저장

고급 AI 표·차트 생성 및 편집

스마트 개체 이름 자동 지정 및 태그 기반 관리

단, 다른 확정 기능을 구현하기 위해 내부적으로 필요한 최소한의 메타데이터, 오류 검사, 개체 식별 기능은 허용한다.

사용자가 승인하지 않은 독립 기능으로 확장하지 않는다.

또한 별도로 승인되지 않은 'AI 사진 분석 및 설명문 자동 생성' 기능은 독립 메뉴로 추가하지 않는다. 단, 기존에 확정된 AI 장표 생성 과정에서 입력 사진을 이해하는 기본 능력은 유지한다.

24. 안전성과 데이터 처리

원본 파일을 기본적으로 보존한다.

삭제 및 대규모 편집은 사용자 승인을 받는다.

API 키는 서버에만 저장한다.

사용자의 데이터 접근 권한을 검증한다.

Supabase에서는 필요한 테이블에 RLS를 적용한다.

불필요한 외부 데이터 전송을 피한다.

업로드 자료의 저장 기간 및 삭제 정책을 명확히 한다.

이미지 생성 및 번역에는 처리 비용이 발생할 수 있음을 고려한다.

AI가 생성한 편집 명령은 검증 후에만 실행한다.

AI가 사용자의 프레젠테이션 내용을 임의로 삭제하거나 다른 슬라이드를 변경해서는 안 된다.

28. 최종 개발 원칙

이 프로젝트의 최종 목표는 사용자가 Microsoft PowerPoint를 열고, PPT AI Studio 애드인에서 다음과 같은 작업을 자연스럽게 수행하는 것이다.

"현장 사진 4장을 넣었으니 안전조회 장표로 만들어줘."

"빨간색 화살표를 전체 PPT에서 삭제해줘."

"2번 사진과 4번 사진 위치를 바꿔줘."

"사진 하나를 삭제했으니 나머지 사진을 자동으로 재배치해줘."

"이 장표를 베트남어로 번역해줘. 한국어 원문은 유지하고 아래에 번역문을 추가해줘."

"이 PPT 전체를 중국어로 번역하고 원본 슬라이드는 그대로 남겨줘."

"이 PDF를 임원보고용 장표로 만들어줘."

"제목만 수정하고 나머지 요소는 절대로 변경하지 마."

이 모든 작업이 실제 PowerPoint 내에서 가능하도록 설계한다.

지금 바로 실행할 작업

우선 기존 저장소의 구조와 설정을 분석한다.

그다음 현재 PowerPoint 및 Office.js 공식 개발 문서를 참고하여 구현 가능성과 제약을 정리한다.

이후 Phase 1에 해당하는 실제 실행 가능한 MVP를 구현한다.

단순한 계획서나 목업으로 종료하지 않는다.

필요한 코드를 작성하고, 빌드와 가능한 테스트를 실행하며, PowerPoint에서 사이드로드할 수 있는 상태까지 작업한다.

PowerPoint가 설치된 Windows 환경에서만 검증할 수 있는 부분은 별도로 표시하고, 검증되지 않은 기능을 동작 확인 완료라고 주장하지 않는다.
