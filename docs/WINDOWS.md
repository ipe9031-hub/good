# Windows PowerPoint 설치 및 실제 검증

## 배포형 사용 (개발 인증서 설치 불필요)

https://good-red.vercel.app/을 사용하는 [배포형 설치 안내](INSTALL-HOSTED.md)를 먼저 확인하세요. 배포형 설치 ZIP의 `manifest.xml`을 아래 공유 폴더 카탈로그 절차로 등록하면 됩니다. 이 경우 Node.js와 로컬 서버는 필요 없습니다.

아래 ‘준비’는 localhost에서 소스를 개발할 때에만 필요합니다.

## 준비

- Windows 10/11, 최신 Microsoft 365 PowerPoint, WebView2, Node.js 22/24 LTS
- 개인 또는 조직이 허용한 테스트용 PC. 원본 PPT 대신 **다른 이름으로 저장한 복제본**으로 시험합니다.
- `Windows-Setup.cmd` → `Windows-Start.cmd` 순으로 실행합니다. 각각 오류가 없는지 확인합니다.
- 직접 실행하려면 저장소 루트에서 `npm ci`, `npm run certs`, `npm run build`, `npm run dev`.
- `https://localhost:3000`과 `/assets/icon-32.png`가 HTTPS 경고 없이 열려야 합니다. 서버 창을 닫으면 애드인도 작동하지 않습니다.

소스 ZIP에서 로컬 개발 서버를 사용할 때는 `manifest.development.xml`을 테스트 카탈로그에 복사하세요. ZIP의 기본 `manifest.xml`은 온라인 서버용입니다. GitHub 저장소 자체의 `manifest.xml`은 계속 개발용 템플릿입니다.

## 공식 공유 폴더 카탈로그로 사이드로드

XML manifest를 사용하는 Microsoft 공식 Windows 테스트 방식입니다. 레지스트리를 자동으로 수정하지 않습니다.

1. `C:\PPTAIStudioCatalog` 폴더를 만들고 `manifest.xml`을 복사합니다. 소스 전체나 인증서를 공유하지 마세요.
2. 폴더 속성 → 공유 → 공유에서 본인 계정에 필요한 권한만 부여합니다. Everyone 전체 권한은 사용하지 않습니다. 공유 경로(예: `\\YOUR-PC\PPTAIStudioCatalog`)를 기록합니다.
3. PowerPoint → 파일 → 옵션 → 보안 센터 → 보안 센터 설정 → 신뢰할 수 있는 추가 기능 카탈로그를 엽니다.
4. 공유 UNC 경로를 카탈로그 URL에 넣고 카탈로그 추가 → 메뉴에 표시를 체크합니다.
5. PowerPoint를 완전히 닫았다가 다시 엽니다.
6. 홈 → 추가 기능 → 고급 (버전에 따라 삽입 → 내 추가 기능) → 공유 폴더에서 **PPT AI Studio**를 선택해 추가합니다.
7. **PPT AI Studio** 리본 탭 → **스튜디오 열기**. 우측 작업창에서 연결됨을 확인합니다.

공유 폴더 기능이 보안 정책으로 차단되면 조직 관리자의 지원이 필요합니다. 이것은 개발 사이드로드이며 제품 설치 또는 조직 배포 완료를 의미하지 않습니다.

v0.2.2에서는 빠른 삽입 메뉴를 제거했습니다. 시험용 개체는 PowerPoint 기본 메뉴에서 추가합니다.

## 반드시 실행할 실기 체크리스트 (현재 미실행)

| 절차 | 기대 결과 | 결과 기록 |
|---|---|---|
| 파일 복사 후 애드인 등록, 리본 클릭 | 리본 버튼 및 우측 한국어 작업창 | 미검증 |
| 슬라이드 2장 생성, 1장 선택, 새로고침 | 전체 2장, 선택 1장, ID 표시 | 미검증 |
| 텍스트/사진/도형 선택 | 이름·유형·좌표·크기 표시 | 미검증 |
| 개체 한 개 선택 후 위치/크기 변경 | 해당 개체만 변경 | 미검증 |
| 개체 두 개 선택 후 삭제 미리보기 | 개수와 이름 표시, 취소 시 보존 | 미검증 |
| 삭제 승인 | 선택한 개체만 삭제 | 미검증 |
| 삭제 확인창을 연 후 PowerPoint에서 선택 변경 → 적용 | 대상 변경 오류, 작업 중단 | 미검증 |
| 여러 슬라이드 선택 후 삽입 | 한 장만 선택하라는 오류 | 미검증 |
| 실제 Ctrl+Z 및 파일 저장/재열기 | 변경 취소 및 저장 동작 확인 | 미검증 |
| 추가 기능 닫기/재실행, 인증서/네트워크 오류 | 재연결 및 이해 가능한 상태 확인 | 미검증 |

테스트 시 Office 버전/빌드/업데이트 채널, Windows 버전, 결과를 기록합니다. Office.js 배치는 부분 실패 시 트랜잭션 롤백을 보장하지 않으므로 오류 후 슬라이드를 확인하세요. 사진 삽입은 Common API 호출 직전 선택 확인 후 호스트에 전송되며, 호출 도중의 선택 변화는 원자적으로 잠글 수 없습니다. 완료까지 PowerPoint의 선택을 변경하지 마세요.

## 제거

추가 기능을 제거하고 보안 센터에서 해당 테스트 카탈로그 항목만 삭제합니다. 개발 인증서가 더 이상 필요하지 않으면 다른 Office 개발 프로젝트 사용 여부를 확인한 뒤 `npx office-addin-dev-certs uninstall`을 실행합니다. Office 전체 캐시를 일괄 삭제하는 자동 스크립트는 제공하지 않습니다.

## 인증서 등록 거부: E_ACCESSDENIED / 0x80070005

이 오류는 Vite 코드 오류가 아니라 Windows 신뢰 저장소에 개발 CA를 등록하지 못한 상태입니다. 기본 설치 대상은 `CurrentUser\Root`이며 관리자 권한이 항상 필요한 것은 아닙니다.

1. 같은 Windows 계정에서 `Windows-Trust-Certificate.cmd`를 실행합니다. 이 도구는 기존 `%USERPROFILE%\.office-addin-dev-certs\ca.crt`의 공개 인증서 정보를 표시하고, 승인 후 Windows 기본 `certutil -user -addstore Root`로 현재 사용자에게 등록합니다. 인증서를 재생성하지 않습니다.
2. 표시된 인증서가 자신이 방금 생성한 Office 개발 인증서인지 확인한 뒤에만 승인합니다. 출처 불명의 인증서를 신뢰하지 마세요.
3. 성공하면 `Windows-Start.cmd`를 다시 실행하고 `Local: https://localhost:3000/`을 확인합니다.
4. 같은 오류가 지속되면 사용자가 등록을 취소했는지, Windows/보안 프로그램/조직 정책이 사용자 루트 인증서 등록을 차단하는지 확인해야 합니다. 회사 PC에서는 관리자에게 이 개발 인증서 등록을 요청하세요. 정책을 우회하거나 TLS 검증을 끄지 않습니다.

기존 ZIP에서도 일반 명령 프롬프트에서 아래 명령으로 같은 등록을 시도할 수 있습니다. 인증서 파일이 존재하며 본인이 만든 파일인지 먼저 확인하세요.

```bat
certutil -user -addstore Root "%USERPROFILE%\.office-addin-dev-certs\ca.crt"
```

새 버전은 `npm run dev`에서 인증서를 자동 생성/등록하지 않고 검증만 수행합니다. 신규 설치 또는 만료 갱신은 `npm run certs`로 명시적으로 실행합니다. Windows에서 이 복구 도구의 실기 검증은 아직 수행하지 못했습니다.
